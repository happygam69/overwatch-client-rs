## The recipe that scales to the rest

The method that opened the UI, input, camera and audio systems in one pass, and
that the remaining rows should use:

1. `search_strings` on the module image for the system's vocabulary (vendor
   names, config-var prefixes, class-name strings, file paths);
2. RIP-relative scan of the module image for each chosen anchor (the scan tool
   pattern: 64-bit `lea/mov` with `mod=00, rm=101`, target = next-IP +
   disp32). Config-var names and class-name strings reliably have **exactly
   one** referencing site;
3. decompile the referencing function in the Ghidra project, and — where the
   function is not analyzed or an independent read is wanted — wrap the
   capture region as a minimal PE (`dev/mkpe.py`) and read it through REA;
4. record the addresses, the structure, and what remains, in the system's
   document, and add or update its row here.

**The wall the recipe hits, and how to read it.** If an anchor has *no*
reference anywhere — not RIP-relative in code, not a pointer (64- or 32-bit) in
any captured data, in either capture — then the code that would use it is not
in the captures at all, and the correct result is a **capture requirement**, not
more string mining. Three systems have landed on that wall so far: the renderer
(row 17), the animation evaluator (row 15) and the lobby state machine
(row 20). A related but different outcome is statescript's (row 5): the
*immediates* are absent (no class-hash dispatch in either capture) while the
runtime code itself **is** captured — so there the correct reading is "the
thread was wrong", not "the capture is missing".

**When the capture is clean but the route is wrong**, switch anchors from
hashes/immediates to *runtime objects*: find a constructed runtime object (its
constructor read by disassembly), then read its consumers. The statescript
variable pool and state registry were reached exactly that way.

Vendors found in one sweep, useful for future anchoring: Wwise 2022.1 (audio),
dear imgui with docking (UI), Domino (in-house physics), and the `bc*`
(Blizzard containers/math) prefixture. The build provenance string
(`D:\Madness\production\Worker\2_25_0_0\...`) confirms the 2.25.0.0.154088
capture.
