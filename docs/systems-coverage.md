# Coverage: every client system

One line per system: what is read, what is open, and where the findings live.
"Read" means a path or value with an address in `Overwatch.exe`, or a value read
from the install — not a full reimplementation. The work queue is
[`open-questions.md`](open-questions.md).

The engine ring is separate from the replay: `0x387` is a batch A/B submission (16-byte CPU→GPU upload, 8-byte GPU→CPU readback), not a draw; no record-id -> replay-opcode translation exists, and the ring consumer is open. `ow-render::batch` implements the read record and transfer layouts with synthetic tests. **A client capture is impossible under the anti-cheat**, so the proof is read + synthetic record streams, not capture; D10/pixels are not provable. ## Not in scope

- **Network protocol and matchmaking** — not read; no doc retained.
- **UI implementation** — the client uses imgui; not a gameplay target.
- **Renderer behaviour** → mapped in `formats/renderer.md`; it is not a
  gameplay claim until a renderer stage passes the gate. The viewer remains
  viewer-only.
- **Anti-cheat and loader internals** — not part of gameplay behaviour.
